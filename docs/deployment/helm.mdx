The project publishes `llm-proxy` as a conventional HTTPS Helm repository at `https://helm-35xkhylwd67f.r5d.app`. GitHub Actions also maintains the packaged chart and `index.yaml` on the `gh-pages` branch as a portable repository snapshot.

## Install from the chart repository

<Steps>
  <Step title="Add the repository">
    ```bash
    helm repo add ai-gateway https://helm-35xkhylwd67f.r5d.app
    helm repo update
    ```
  </Step>
  <Step title="Create a namespace and deployment secrets">
    ```bash
    kubectl create namespace llm-proxy

    kubectl -n llm-proxy create secret generic llm-proxy-secrets \
      --from-literal=DATABASE_URL='postgres://...' \
      --from-literal=BETTER_AUTH_SECRET="$(openssl rand -base64 48)" \
      --from-literal=SETTINGS_ENCRYPTION_KEY="v1:$(openssl rand -base64 32)"
    ```
  </Step>
  <Step title="Install the chart">
    ```bash
    helm upgrade --install proxy ai-gateway/llm-proxy \
      --namespace llm-proxy \
      --set image.repository=ghcr.io/your-org/llm-proxy \
      --set image.tag=0.1.0 \
      --set config.baseUrl=https://proxy.example.com \
      --set secrets.existingSecret=llm-proxy-secrets \
      --set ingress.enabled=true \
      --set ingress.className=traefik \
      --set ingress.host=proxy.example.com
    ```
  </Step>
  <Step title="Verify the rollout">
    ```bash
    kubectl -n llm-proxy rollout status deployment/proxy-llm-proxy
    kubectl -n llm-proxy get pods,service,ingress
    ```
  </Step>
</Steps>

<Warning>
  Keep public Ingress disabled until you can complete `/setup` through a protected tunnel. The first successful setup request creates the initial administrator.
</Warning>

## Use the bundled TimescaleDB

For a small installation, the chart can deploy its pinned TimescaleDB/PostgreSQL 17 image:

```bash
helm upgrade --install proxy ai-gateway/llm-proxy \
  --namespace llm-proxy --create-namespace \
  --set image.repository=ghcr.io/your-org/llm-proxy \
  --set image.tag=0.1.0 \
  --set config.baseUrl=https://proxy.example.com \
  --set postgresql.enabled=true \
  --set postgresql.password="$(openssl rand -base64 36)" \
  --set postgresql.persistence.storageClass=rook-ceph-block \
  --set postgresql.persistence.size=10Gi \
  --set secrets.values.authSecret="$(openssl rand -base64 48)" \
  --set secrets.values.settingsEncryptionKey="v1:$(openssl rand -base64 32)"
```

The bundled database uses a `ReadWriteOnce` PVC. Set `postgresql.persistence.storageClass` explicitly for your cluster. Use external TimescaleDB when you need database high availability or managed backups.

## Required existing-secret keys

When `secrets.existingSecret` is set, the Secret must contain:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | TimescaleDB connection URL |
| `BETTER_AUTH_SECRET` | Long random session/authentication secret |
| `SETTINGS_ENCRYPTION_KEY` | `v1:` followed by base64 for exactly 32 random bytes |

You can rename the key mappings with `secrets.keys.*`.

## Install from a checkout

```bash
helm upgrade --install proxy ./charts/llm-proxy \
  --namespace llm-proxy --create-namespace \
  --values my-values.yaml
```

## Chart publication

The `Release Helm chart` GitHub Actions workflow performs two publication jobs:

1. It packages every new chart version, creates a GitHub release, and updates the `gh-pages` branch's `index.yaml` snapshot.
2. It builds and pushes a static Nginx repository image to GHCR with `index.yaml` generated for the hosted URL.

The static server is deployed from `deploy/helm-repository.yaml`. Bump `version` in `charts/llm-proxy/Chart.yaml` for every chart release; the GitHub release step skips versions that already exist, while the repository image always reflects the current chart source.

```text
Repository: https://helm-35xkhylwd67f.r5d.app
Index:      https://helm-35xkhylwd67f.r5d.app/index.yaml
```

GitHub Pages cannot serve this private repository on the current GitHub plan, so the public Kubernetes-hosted server is the canonical Helm URL. If the repository becomes public or the plan changes, the existing `gh-pages` branch can be enabled directly under **Settings → Pages**.
