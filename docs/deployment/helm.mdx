The project publishes `ai-gateway` as a conventional HTTPS Helm repository on GitHub Pages at `https://ricsam.github.io/ai-gateway`. GitHub Actions packages each chart release, updates the `gh-pages` branch, and deploys that branch with GitHub Pages.

The chart pins a public, pre-built `ghcr.io/ricsam/ai-gateway:sha-<full-commit-sha>` image by default. The image supports Linux AMD64 and ARM64; chart `appVersion` identifies the pinned application build.

## Install from the chart repository

<Steps>
  <Step title="Add the repository">
    ```bash
    helm repo add ai-gateway https://ricsam.github.io/ai-gateway
    helm repo update
    ```
  </Step>
  <Step title="Create a namespace and deployment secrets">
    ```bash
    kubectl create namespace ai-gateway

    kubectl -n ai-gateway create secret generic ai-gateway-secrets \
      --from-literal=DATABASE_URL='postgres://...' \
      --from-literal=BETTER_AUTH_SECRET="$(openssl rand -base64 48)" \
      --from-literal=SETTINGS_ENCRYPTION_KEY="v1:$(openssl rand -base64 32)"
    ```
  </Step>
  <Step title="Install the chart">
    ```bash
    helm upgrade --install ai-gateway ai-gateway/ai-gateway \
      --namespace ai-gateway \
      --set config.baseUrl=https://gateway.example.com \
      --set secrets.existingSecret=ai-gateway-secrets \
      --set ingress.enabled=true \
      --set ingress.className=traefik \
      --set ingress.host=gateway.example.com
    ```
  </Step>
  <Step title="Verify the rollout">
    ```bash
    kubectl -n ai-gateway rollout status deployment/ai-gateway-ai-gateway
    kubectl -n ai-gateway get pods,service,ingress
    ```
  </Step>
  <Step title="Create the first administrator">
    Complete first-boot setup from inside the cluster with the image's [management CLI](/docs/administration/cli), which asks for the password:

    ```bash
    kubectl -n ai-gateway exec -it deployment/ai-gateway-ai-gateway -- \
      aigctl setup init --username admin --email admin@example.com --name "Gateway Admin"
    ```
  </Step>
</Steps>

To override the chart's pinned application build, select another published immutable image tag:

```bash
helm upgrade --install ai-gateway ai-gateway/ai-gateway \
  --namespace ai-gateway \
  --set image.tag=sha-<full-commit-sha> \
  --reuse-values
```

Main-branch builds publish `latest` and `sha-<full-commit-sha>`. Git tags pushed directly to GitHub also publish a matching image tag.

<Warning>
  Until setup is complete, anyone who reaches `/setup` can create the initial administrator. Run `aigctl setup init` as soon as the rollout finishes, or keep public Ingress disabled until you have completed `/setup` through a protected tunnel.
</Warning>

## Manage the gateway with kubectl

The image includes `aigctl`, which manages users, groups, keys, credits, settings, AWS credentials, login providers, usage and audit history from inside the pod, authorized by your access to it:

```bash
kubectl -n ai-gateway exec -it deployment/ai-gateway-ai-gateway -- aigctl users list
kubectl -n ai-gateway exec -it deployment/ai-gateway-ai-gateway -- aigctl --help
```

See [Management CLI](/docs/administration/cli). Treat `pods/exec` permission on the namespace as full administrative access to the gateway.

## Use the bundled TimescaleDB

For a small installation, the chart can deploy its pinned TimescaleDB/PostgreSQL 17 image:

```bash
helm upgrade --install ai-gateway ai-gateway/ai-gateway \
  --namespace ai-gateway --create-namespace \
  --set config.baseUrl=https://gateway.example.com \
  --set postgresql.enabled=true \
  --set postgresql.password="$(openssl rand -base64 36)" \
  --set postgresql.persistence.storageClass=rook-ceph-block \
  --set postgresql.persistence.size=10Gi \
  --set secrets.values.authSecret="$(openssl rand -base64 48)" \
  --set secrets.values.settingsEncryptionKey="v1:$(openssl rand -base64 32)"
```

The bundled database uses a `ReadWriteOnce` PVC. Set `postgresql.persistence.storageClass` explicitly for your cluster. Use external TimescaleDB when you need database high availability or managed backups.

## Required existing-secret keys

When `secrets.existingSecret` is set, the Secret must contain:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | TimescaleDB connection URL |
| `BETTER_AUTH_SECRET` | Long random session/authentication secret |
| `SETTINGS_ENCRYPTION_KEY` | `v1:` followed by base64 for exactly 32 random bytes |

You can rename the key mappings with `secrets.keys.*`.

## Client IP addresses

Sign-in limits each client to 3 attempts per 10 seconds, and every session records the address it signed in from. The gateway finds a request's client address in `X-Forwarded-For` when that header holds a single address. Requests without one, or with a list of addresses as proxies append them, all share one limit, so a few failed sign-ins can briefly block everyone's, and the log says `Rate limiting could not determine a client IP` once. Behind proxies, tell the gateway where the client's address is:

| Value | Environment variable | Use it when |
| --- | --- | --- |
| `config.clientIpHeaders` | `CLIENT_IP_HEADERS` | A proxy in front of the gateway sets a header to the client's address alone, replacing whatever the client sent, such as Cloudflare's `CF-Connecting-IP`. Headers are read in order, so add `x-forwarded-for` to fall back to it. |
| `config.trustedProxies` | `TRUSTED_PROXIES` | Proxies append to `X-Forwarded-For`, so it holds a list such as `203.0.113.7, 10.42.0.12`. List the proxies' addresses or CIDR ranges; the client address is the rightmost one that isn't a proxy's. |

```bash
# Every request reaches the gateway through Cloudflare (proxied DNS or Cloudflare Tunnel)
helm upgrade ai-gateway ai-gateway/ai-gateway --namespace ai-gateway --reset-then-reuse-values \
  --set 'config.clientIpHeaders={cf-connecting-ip}'

# The ingress controller's pods, in 10.42.0.0/16, append to X-Forwarded-For
helm upgrade ai-gateway ai-gateway/ai-gateway --namespace ai-gateway --reset-then-reuse-values \
  --set 'config.trustedProxies={10.42.0.0/16}'
```

These settings need chart 0.1.20 or later. `--reset-then-reuse-values` (Helm 3.14 or later) keeps your earlier values and takes the new chart's defaults, such as its image; `--reuse-values` would keep the previous chart's image, which ignores these settings.

The environment variables take the same values separated by commas. The gateway refuses to start when an entry isn't a header name, an IP address or a CIDR range, and the chart restarts the pods when these values change.

<Warning>
  Any client can send these headers itself. Name a header only when every request reaches the gateway through a proxy that sets it, and list only your proxies' own addresses as trusted, not a private range that clients also connect from. Trusted-header sign-in doesn't use these settings: it always checks the address of the connection itself.
</Warning>

## Install from a checkout

```bash
helm upgrade --install ai-gateway ./charts/ai-gateway \
  --namespace ai-gateway --create-namespace \
  --values my-values.yaml
```

## Image and chart publication

The `Publish container image` GitHub Actions workflow builds the Dockerfile for Linux AMD64 and ARM64. Pull requests build without publishing; pushes to `main` publish `latest` and `sha-<full-commit-sha>` to `ghcr.io/ricsam/ai-gateway`, while Git tags also publish a matching tag. Published images include provenance and an SBOM.

The `Release Helm chart` workflow lints and packages every new chart version, creates a GitHub release, updates the `gh-pages` branch's `index.yaml`, and deploys the branch through GitHub Pages.

Publish and verify the application image first. Bump `version` in `charts/ai-gateway/Chart.yaml`, update `appVersion` and the default `image.tag` to the published `sha-<full-commit-sha>`, then push to `main`. Chart versions are immutable; the release step skips a version that already exists.

```text
Repository: https://ricsam.github.io/ai-gateway
Index:      https://ricsam.github.io/ai-gateway/index.yaml
```
