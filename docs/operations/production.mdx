## Health endpoints

| Endpoint | Check | Expected response |
| --- | --- | --- |
| `/healthz` | Process is serving HTTP | `{"status":"ok"}` |
| `/readyz` | Database accepts a query | `{"status":"ready"}` |

Readiness does not require AWS. Use the AWS connection test and a low-cost model request to verify the provider path.

## Backups

Back up TimescaleDB and `SETTINGS_ENCRYPTION_KEY` as one recovery unit. Retain `BETTER_AUTH_SECRET` if restored browser sessions should remain valid.

Use either:

- Timescale-aware `pg_dump` and `pg_restore` with the same compatible extension installed at the destination.
- A storage or managed-database snapshot that includes extension catalogs.

Test restore procedures regularly.

## Restore verification

<Steps>
  <Step title="Prepare an empty compatible database">
    Install the TimescaleDB extension before restoring.
  </Step>
  <Step title="Restore data and secrets">
    Restore the database and deploy the matching encryption key.
  </Step>
  <Step title="Run current migrations">
    Apply schema changes from the application version you are deploying.
  </Step>
  <Step title="Verify Timescale objects">
    Check `timescaledb_information.hypertables`, all three credit-event continuous aggregates (with `materialized_only` false, so analytics include recent usage), aggregate refresh jobs, and the compression policy.
  </Step>
  <Step title="Test the application">
    Verify readiness, administrator login, model discovery, a low-cost completion, credit settlement, and analytics.
  </Step>
</Steps>

## Release discipline

Use immutable image tags in production and run migrations before the application rollout. Do not deploy `latest` when rollback and auditability matter.

## Speech to text

The [speech-to-text endpoints](/docs/speech-to-text) decode every upload but PCM WAV with ffmpeg, which the container image includes. A gateway run from source needs `ffmpeg` on `PATH`; without it, those endpoints accept only PCM WAV files and answer others with `unsupported_audio_format`.

- ffmpeg runs as a child process of the gateway for each decoding pass of a transcription, at most two per file. It reads the upload from a pipe, with the demuxer that the file's bytes name and no protocol but the pipe, so it cannot open other files or URLs, and it decodes only the first audio track. It is stopped when the request ends, or when it produces no audio for 2 minutes while the gateway waits for it.
- A transcription holds its upload, up to 25 MB, in memory, with a few blocks of decoded audio and the chunks being transcribed. It writes no temporary files, so a read-only root filesystem works.
- A transcription responds when its last chunk is transcribed, which takes longer for long files and for Voxtral Small. Give proxies in front of the gateway a response timeout to match.

## Security checklist

- Terminate public traffic with HTTPS and set `BASE_URL` to that exact origin.
- Behind proxies, set where the client's address is (`config.clientIpHeaders` or `config.trustedProxies`), so that sign-in rate limits count each client separately. See [Client IP addresses](/docs/deployment/helm#client-ip-addresses).
- Keep TimescaleDB private.
- Use long random deployment secrets and a secret manager.
- Restrict AWS credentials to required Bedrock actions and resources.
- Deploy image updates: the image's ffmpeg decodes untrusted uploads for the speech-to-text endpoints.
- Give automation management keys the smallest scope and an expiry.
- Keep at least two enabled administrators.
- Do not expose `/setup` before an operator can complete it; `aigctl setup init` completes it from inside the cluster.
- Treat `pods/exec` on the gateway as full administrative access: [aigctl](/docs/administration/cli) in the container manages the gateway without a key.
- Treat trusted-header mode as privileged network integration.
- Review audit events and usage anomalies.

## Recovery

Run `aigctl users set-password` in the gateway container, or `bun run admin:recover` with database access, to restore a local administrator (see [First boot](/docs/administration/first-boot#offline-administrator-recovery)). If `SETTINGS_ENCRYPTION_KEY` is lost, encrypted AWS and login-provider settings cannot be decrypted; restore the key from backup or clear and reconfigure those settings through a controlled database recovery.
