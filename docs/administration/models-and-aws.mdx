The enabled model catalog is shared by the public API and the built-in playground. All inference is routed to AWS Bedrock.

## Configure Bedrock credentials

Open **Admin → Branding & AWS** and provide:

- A default AWS region, such as `us-east-1`.
- A static access key ID.
- A secret access key.
- An optional session token for temporary credentials.

Secret fields are encrypted before storage and never returned as plaintext. Save the configuration, select a configured model, and run the connection test.

<Note>
  The current runtime requires database-configured static credentials. ServiceAccount annotations in the Helm chart are generic infrastructure and do not enable workload-identity authentication.
</Note>

## Add a model

Open **Admin → Models** and configure:

| Field | Purpose |
| --- | --- |
| Bedrock model ID | Exact model, inference profile, or provisioned-throughput identifier sent to AWS |
| Display name | Human-readable dashboard label |
| Input/output price | USD per million tokens used for credit settlement |
| Cache prices | Optional read, 5-minute write, and 1-hour write prices per million tokens |
| Context window | Informational input capacity shown to users |
| Max output tokens | Hard upper bound enforced by the proxy (except Amazon Nova 2 at `high` reasoning effort, which rejects an output cap) |
| Region override | Uses a region different from the AWS default |
| Reasoning / effort | Honors `reasoning_effort` requests and enables the two settings below |
| Reasoning control | How effort is sent to Bedrock; **Automatic** detects it from the model ID |
| Default effort | Effort applied when a request omits `reasoning_effort`; **Model default** leaves it to the request |
| Managed cache | Inserts supported cache points into Converse and Anthropic Invoke requests |
| Enabled | Makes the model available to API users |

Use **Test model before saving** to verify that the identifier, region, credentials, and Bedrock access are correct.

## Reasoning effort

With **Reasoning / effort** enabled, API clients and the playground can send `reasoning_effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`). The **Reasoning control** decides the Bedrock request shape:

| Control | Bedrock request | Use for |
| --- | --- | --- |
| Claude adaptive thinking + effort | `thinking: {type: "adaptive"}` and `output_config.effort` | Claude Opus 4.6, Sonnet 4.6, and newer |
| Claude extended thinking budget | `thinking: {type: "enabled", budget_tokens}` | Claude 4.5 and earlier, Claude 3.7 Sonnet |
| Amazon Nova reasoning effort | `reasoningConfig.maxReasoningEffort` | Amazon Nova 2 |
| OpenAI reasoning effort | `reasoning_effort` | OpenAI gpt-oss |

**Automatic** recognizes Bedrock model IDs, cross-Region inference profile IDs (`us.`, `eu.`, `global.`, and similar prefixes), and ARNs that contain the model name. The dialog shows what was detected and which effort levels the model accepts. Unsupported levels in requests are lowered to the nearest supported level. Identifiers that do not reveal the model — for example application inference profile or provisioned-throughput ARNs — keep the historical Claude thinking-budget behavior, so choose the matching control explicitly for them.

<Warning>
  Newer Claude models (Opus 4.7 and later, and Claude 5 models) reject thinking budgets. Leave the control on **Automatic** or select **Claude adaptive thinking + effort** for them.
</Warning>

A **Default effort** makes reasoning apply even to clients that never send `reasoning_effort`, which raises output-token usage. **None** as a default turns thinking off on models that think by default and allow disabling it. Effort changes start a new prompt-cache prefix, so prefer a stable default. Reasoning tokens are billed as output tokens.

## Alias reasoning ownership

In **Admin → Model aliases**, select the upstream model and choose **Reasoning configured by**:

- **Alias (pinned)** is the default for new and existing aliases. Configure thinking and effort explicitly; clients cannot override these settings. Unsupported pinned combinations are rejected.
- **Client (OpenAI options)** hides the pinned controls. Clients and the playground can choose `reasoning_effort` using the upstream model’s supported controls. Omission uses the upstream’s configured default effort, then its provider default. Stored alias `thinking` and `effort` values are retained but ignored while in client mode; review them when switching back to pinned mode.

The alias saves this choice as `reasoningSource: "alias"` or `"client"`. App tier IDs inherit their mapped alias’s ownership. Client-mode native Bedrock requests preserve caller-supplied reasoning options rather than applying the alias’s pinned settings. Pricing and limits remain inherited from the upstream in either mode. See [Chat Completions](/docs/chat-completions) for request examples.

## Image URL downloads

The OpenAI-compatible API accepts images as base64 data URLs or `http(s)` URLs. **Admin → Brand & AWS → Inference → Download image URLs** controls whether the gateway downloads image URLs (enabled by default). Downloads only reach public addresses on default ports, follow at most three re-validated redirects, and are limited to 10 seconds and 3.75 MB per image. Turn downloads off if the deployment must not make outbound requests on behalf of API clients; data URLs keep working. The same setting is available through the management API at `/management/v1/settings`.

## Region selection

A model's region override wins over the default region. The runtime caches Bedrock clients by configuration revision and region. Saving AWS settings invalidates the client cache so new requests use the current credentials.

## Throughput and Bedrock quotas

Amazon Bedrock limits the tokens and requests per minute of each model in each Region. A quota increase request asks for steady-state and peak tokens per minute (TPM) and requests per minute (RPM), and for the average input and output tokens per request. The **Throughput** card shows these values for the gateway's metered requests:

- **Admin → Analytics** for all users, and the user and group pages for one user or the current members of a group.
- **Profile, API & usage** for the signed-in user's own requests.

The card summarizes all models together and lists each upstream model separately. Quotas apply per model, so use the model's row in a request. Requests to aliases and app tiers count toward their upstream model. The selected **Range** sets the window; the **Interval** control doesn't change these values.

| Value | Definition |
| --- | --- |
| Steady state TPM / RPM | Tokens or requests divided by the minutes of the window's active hours. The window is split into one-hour periods counted from its start, and a period is active if it had at least one request. Idle nights and weekends don't lower the value, and **Last 60 minutes** is a single period. |
| Peak TPM / RPM | Tokens or requests in the busiest calendar minute, with the time it started. For all models together, it's the busiest minute of their combined traffic. |
| Avg input tokens / request | Uncached input plus cache-write tokens, divided by requests. The card also shows the cache-read tokens per request, which aren't included. |
| Avg output tokens / request | Output tokens, including reasoning tokens, divided by requests. |

Tokens follow Bedrock's quota accounting: input, cache writes and output count toward TPM quotas, and cache reads don't. Bedrock also multiplies output tokens by a model-specific burndown rate, for example 5× for many Claude models (see [How tokens are counted in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)). These values don't include it. To estimate steady-state quota usage, multiply the average output by the model's rate: steady-state RPM × (average input + burndown rate × average output).

When you size a request, keep in mind that:

- Only requests completed through this gateway are counted. Other Bedrock clients in the same AWS account and Region share its quotas.
- Throttled requests aren't recorded, so traffic that already reaches a quota shows that quota as its peak. Ask for headroom above the observed peak.
- Usage is recorded per upstream model ID, not per Region. A model with a region override uses that Region's quotas.

Automation can read the same values from the management API with the `usage.read` scope. Add `userId` or `groupId` to limit the scope:

```bash
curl "https://gateway.example.com/management/v1/analytics/throughput?timeRange=month" \
  -H "Authorization: Bearer $AI_GATEWAY_MANAGEMENT_KEY"
```

The response's `data.summary` covers all models and `data.models` lists each upstream model, most tokens first. Each entry has `requests`, `tokens`, `activeHours`, `steadyStateTpm`, `steadyStateRpm`, `peakTpm`, `peakTpmAt`, `peakRpm`, `peakRpmAt`, `avgInputTokensPerRequest`, `avgOutputTokensPerRequest` and `avgCacheReadTokensPerRequest`. Rates aren't rounded.

The values are computed from every metered request in the range when they're requested, so they include the current minute. Peaks need one-minute detail, which the hourly and daily aggregates behind the charts don't have, so long ranges take longer on busy installations. With 40,000 requests a day, the all-users card took about 1.5 seconds for **Last 30 days** and 12 seconds for **Last 365 days**; one user's took 0.1 and 1 second.

## Credential rotation

<Steps>
  <Step title="Create replacement credentials in AWS">
    Grant only the Bedrock permissions and model access the proxy needs.
  </Step>
  <Step title="Save the replacements">
    Enter the new access key ID, secret access key, and optional session token in the dashboard.
  </Step>
  <Step title="Test an enabled model">
    Confirm a real Converse request succeeds in every region in use.
  </Step>
  <Step title="Revoke the old key">
    Remove the former credentials in AWS only after the test succeeds.
  </Step>
</Steps>

Clearing credentials keeps the service healthy but causes inference to return `provider_not_configured` until credentials are restored.
