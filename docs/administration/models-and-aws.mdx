The enabled model catalog is shared by the public API and the built-in playground. All inference is routed to AWS Bedrock.

## Configure Bedrock credentials

Open **Admin → Branding & AWS** and provide:

- A default AWS region, such as `us-east-1`.
- A static access key ID.
- A secret access key.
- An optional session token for temporary credentials.

Secret fields are encrypted before storage and never returned as plaintext. Save the configuration, select a configured model, and run the connection test.

<Note>
  The current runtime requires database-configured static credentials. ServiceAccount annotations in the Helm chart are generic infrastructure and do not enable workload-identity authentication.
</Note>

## Add a model

Open **Admin → Models** and configure:

| Field | Purpose |
| --- | --- |
| Bedrock model ID | Exact model, inference profile, or provisioned-throughput identifier sent to AWS |
| Display name | Human-readable label in the dashboard, and the model's `name` in [`/v1/models`](/docs/chat-completions#listing-models) |
| Input/output price | USD per million tokens used for credit settlement |
| Cache prices | Optional read, 5-minute write, and 1-hour write prices per million tokens |
| Context window | Informational input capacity shown to users, and the model's `context_window` in [`/v1/models`](/docs/chat-completions#listing-models) (`null` when empty) |
| Max output tokens | Hard upper bound enforced by the proxy (except Amazon Nova 2 at `high` reasoning effort, which rejects an output cap), and the model's `max_output_tokens` in [`/v1/models`](/docs/chat-completions#listing-models) |
| Region override | Uses a region different from the AWS default |
| Reasoning / effort | Honors `reasoning_effort` requests and enables the two settings below |
| Reasoning control | How effort is sent to Bedrock; **Automatic** detects it from the model ID |
| Default effort | Effort applied when a request omits `reasoning_effort`; **Model default** leaves it to the request |
| Managed cache | Inserts supported cache points into Converse and Anthropic Invoke requests |
| Enabled | Makes the model available to API users |

Use **Test model before saving** to verify that the identifier, region, credentials, and Bedrock access are correct.

The same settings are available from a terminal with [`aigctl models`](/docs/administration/cli#models-aliases-and-apps) in the gateway container, and to automation at `/management/v1/models` with the `models.read` and `models.write` scopes; see [Management API](/docs/administration/management-api#models-aliases-and-apps). Model aliases and apps have `aigctl aliases`, `aigctl apps`, `/management/v1/model-aliases` and `/management/v1/model-apps`.

```bash
kubectl -n ai-gateway exec deploy/ai-gateway-ai-gateway -- aigctl models create \
  --model-id us.anthropic.claude-opus-4-6-v1 --name "Claude Opus 4.6" --input-price 5 --output-price 25 --thinking on
kubectl -n ai-gateway exec deploy/ai-gateway-ai-gateway -- aigctl aws test "Claude Opus 4.6"
```

## Reasoning effort

With **Reasoning / effort** enabled, API clients and the playground can send `reasoning_effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`). The **Reasoning control** decides the Bedrock request shape:

| Control | Bedrock request | Use for |
| --- | --- | --- |
| Claude adaptive thinking + effort | `thinking: {type: "adaptive"}` and `output_config.effort` | Claude Opus 4.6, Sonnet 4.6, and newer |
| Claude extended thinking budget | `thinking: {type: "enabled", budget_tokens}` | Claude 4.5 and earlier, Claude 3.7 Sonnet |
| Amazon Nova reasoning effort | `reasoningConfig.maxReasoningEffort` | Amazon Nova 2 |
| OpenAI reasoning effort | `reasoning_effort` | OpenAI gpt-oss |

**Automatic** recognizes Bedrock model IDs, cross-Region inference profile IDs (`us.`, `eu.`, `global.`, and similar prefixes), and ARNs that contain the model name. The dialog shows what was detected and which effort levels the model accepts. Unsupported levels in requests are lowered to the nearest supported level. Identifiers that do not reveal the model — for example application inference profile or provisioned-throughput ARNs — keep the historical Claude thinking-budget behavior, so choose the matching control explicitly for them.

<Warning>
  Newer Claude models (Opus 4.7 and later, and Claude 5 models) reject thinking budgets. Leave the control on **Automatic** or select **Claude adaptive thinking + effort** for them.
</Warning>

A **Default effort** makes reasoning apply even to clients that never send `reasoning_effort`, which raises output-token usage. **None** as a default turns thinking off on models that think by default and allow disabling it. Effort changes start a new prompt-cache prefix, so prefer a stable default. Reasoning tokens are billed as output tokens.

## Alias reasoning ownership

In **Admin → Model aliases**, select the upstream model and choose **Reasoning configured by**:

- **Alias (pinned)** is the default for new and existing aliases. Configure thinking and effort explicitly; clients cannot override these settings. Unsupported pinned combinations are rejected.
- **Client (OpenAI options)** hides the pinned controls. Clients and the playground can choose `reasoning_effort` using the upstream model’s supported controls. Omission uses the upstream’s configured default effort, then its provider default. Stored alias `thinking` and `effort` values are retained but ignored while in client mode; review them when switching back to pinned mode.

The alias saves this choice as `reasoningSource: "alias"` or `"client"`. App tier IDs inherit their mapped alias’s ownership. Client-mode native Bedrock requests preserve caller-supplied reasoning options rather than applying the alias’s pinned settings. Pricing and limits remain inherited from the upstream in either mode. See [Chat Completions](/docs/chat-completions) for request examples.

## Image URL downloads

The OpenAI-compatible API accepts images as base64 data URLs or `http(s)` URLs. **Admin → Brand & AWS → Inference → Download image URLs** controls whether the gateway downloads image URLs (enabled by default). Downloads only reach public addresses on default ports, follow at most three re-validated redirects, and are limited to 10 seconds and 3.75 MB per image. Turn downloads off if the deployment must not make outbound requests on behalf of API clients; data URLs keep working. The same setting is available through the management API at `/management/v1/settings`.

## Reasoning replay

Claude builds on its earlier thinking only if its thinking blocks are sent back with later turns, and OpenAI-format clients cannot do that themselves. **Admin → Brand & AWS → Inference → Send Claude's earlier reasoning back** (enabled by default) makes the gateway store the reasoning blocks of every Claude response with thinking on and put them back into the matching assistant turns of later requests. See [Reasoning across turns](/docs/chat-completions#reasoning-across-turns) for what clients need to do.

- Stored reasoning is the model's thinking about the conversation, so treat it like conversation content. It belongs to one user and one upstream model, is kept in the `reasoning_replay_entries` table for 7 days after it was last used, and is deleted with its user. Expired rows are removed hourly.
- Turning the setting off stops storing and replaying reasoning and deletes everything stored; the audit event `settings.updated` records how many entries were deleted. The setting is also available as `reasoningReplayEnabled` at `/management/v1/settings`.
- Replayed reasoning is billed as input, mostly as cache reads, and shows up in usage like other input tokens.
- On Claude Opus, Sonnet and Haiku 5.5 and later, the gateway sends `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` with the `thinking-binding-controls-2026-08-01` beta, so Bedrock drops instead of rejecting reasoning whose conversation changed. If a model rejects these controls, the gateway leaves them out for that model for an hour.
- If Bedrock rejects a request that carries replayed reasoning, the gateway sends it once more without it, so replay never fails a request.

Each request with thinking logs one line, for example:

```text
[OpenAI Proxy] Reasoning replay: request=… model=eu.anthropic.claude-opus-5-5 assistant_turns=12 matched=12 replayed_entries=12 replayed_blocks=14 missing=0 stale=0 unchained=0 binding=drop_block
```

`missing` counts assistant turns without stored reasoning (turns without thinking, or reasoning that expired), `stale` counts stored reasoning left out because the conversation before it changed, and `unchained` counts reasoning left out because a turn before it is missing. Retries without replay log `Reasoning replay rejected, retrying without it`, and blocks Bedrock reports as dropped log `Bedrock dropped replayed reasoning` (non-streaming requests only; ConverseStream does not report them).

To measure the effect on a deployment, `bun run reasoning:ab` runs a multi-step tool task and sends every step twice: with the key of a user whose reasoning is replayed, and with the key of a second user, for whom nothing is stored. It reports output tokens, time and settled cost per step. Set `GATEWAY_URL`, `AI_GATEWAY_API_KEY` and `AI_GATEWAY_CONTROL_API_KEY`; it spends real credits, so cap it with `--max-cost`.

## Speech models

The [speech-to-text endpoints](/docs/speech-to-text) need a model that transcribes an audio file sent through Converse. On Bedrock, these are Mistral's Voxtral models:

| Model | Bedrock model ID | Use for |
| --- | --- | --- |
| Voxtral Mini 3B | `mistral.voxtral-mini-3b-2507` | Fast and cheap transcription: an 8.5-minute recording took about 5 seconds |
| Voxtral Small 24B | `mistral.voxtral-small-24b-2507` | Noisy audio and accents, which it transcribes better; about 2 to 3 times slower |

Amazon Nova Sonic models are speech-to-speech models for bidirectional streaming and don't transcribe files.

Bedrock lists both Voxtral models as Legacy, with an end-of-life date of March 30, 2027. They are offered in-Region only, without cross-Region inference profiles, so configure the plain model ID, and a **Region override** when the default AWS Region doesn't offer it. On November 27, 2026, audio requests worked in `us-east-1`, `us-east-2`, `us-west-2`, `eu-west-1`, `eu-west-2`, `ap-northeast-1`, `ap-south-1`, `ap-southeast-2` and `sa-east-1`. In `eu-central-1`, `eu-north-1` and `eu-west-3`, Converse rejected the model IDs as invalid, although Bedrock's model cards list some of these Regions, so test the Region you choose.

Add each model in **Admin → Models** with:

- Input and output prices from the [Bedrock pricing page](https://aws.amazon.com/bedrock/pricing/). The commands below use example prices, as listed for US Regions: $0.04 per million input and output tokens for Voxtral Mini, and $0.10 per million input and $0.30 per million output tokens for Voxtral Small. Verify them for your Region.
- A context window of 32,000 tokens.
- Max output tokens of at least 4,096. Each chunk of a transcription asks for at most about 1,000 output tokens, capped by this limit, so a much lower limit cuts the transcripts of long chunks short.
- A region override where the default Region doesn't offer the model.

```bash
kubectl -n ai-gateway exec deploy/ai-gateway-ai-gateway -- aigctl models create \
  --model-id mistral.voxtral-mini-3b-2507 --name "Voxtral Mini" --input-price 0.04 --output-price 0.04 \
  --context-window 32000 --max-output-tokens 4096 --region eu-west-1
kubectl -n ai-gateway exec deploy/ai-gateway-ai-gateway -- aigctl models create \
  --model-id mistral.voxtral-small-24b-2507 --name "Voxtral Small" --input-price 0.1 --output-price 0.3 \
  --context-window 32000 --max-output-tokens 4096 --region eu-west-1
kubectl -n ai-gateway exec deploy/ai-gateway-ai-gateway -- aigctl aliases create voxtral-mini --upstream "Voxtral Mini"
kubectl -n ai-gateway exec deploy/ai-gateway-ai-gateway -- aigctl aws test "Voxtral Mini"
```

An alias such as `voxtral-mini` gives clients a short model ID that stays the same when you move it to another upstream model. The AWS credentials need `bedrock:InvokeModel` on the models. **Test model before saving** and `aigctl aws test` send a short text prompt, which Voxtral answers too, so they check the model ID, Region, credentials and model access but not audio; transcribe a short file to check that.

Each chunk of a transcription is a Bedrock request of its own, up to 6 at a time, while analytics count the transcription as one request; see [Throughput and Bedrock quotas](#throughput-and-bedrock-quotas).

## Region selection

A model's region override wins over the default region. The runtime caches Bedrock clients by configuration revision and region. Saving AWS settings invalidates the client cache so new requests use the current credentials.

## Throughput and Bedrock quotas

Amazon Bedrock limits the tokens and requests per minute of each model in each Region. A quota increase request asks for steady-state and peak tokens per minute (TPM) and requests per minute (RPM), and for the average input and output tokens per request. The **Throughput** card shows these values for the gateway's metered requests:

- **Admin → Analytics** for all users or the users and groups selected in its **People** filter, and the user and group pages for one user or the current members of a group.
- **Profile, API & usage** for the signed-in user's own requests.

The card summarizes all models together and lists each upstream model separately. Quotas apply per model, so use the model's row in a request. Requests to aliases and app tiers count toward their upstream model. The selected **Range**, a rolling window or a custom range, sets the window; the **Interval** control doesn't change these values.

| Value | Definition |
| --- | --- |
| Steady state TPM / RPM | Tokens or requests divided by the minutes of the window's active hours. The window is split into one-hour periods counted from its start, and a period is active if it had at least one request. Idle nights and weekends don't lower the value, and **Last 60 minutes** is a single period. A custom range that doesn't span whole hours ends with a shorter period, which counts only its minutes, so `activeHours` can have a fraction. |
| Peak TPM / RPM | Tokens or requests in the busiest calendar minute, with the time it started. For all models together, it's the busiest minute of their combined traffic. |
| Avg input tokens / request | Uncached input plus cache-write tokens, divided by requests. The card also shows the cache-read tokens per request, which aren't included. |
| Avg output tokens / request | Output tokens, including reasoning tokens, divided by requests. |

Tokens follow Bedrock's quota accounting: input, cache writes and output count toward TPM quotas, and cache reads don't. Bedrock also multiplies output tokens by a model-specific burndown rate, for example 5× for many Claude models (see [How tokens are counted in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)). These values don't include it. To estimate steady-state quota usage, multiply the average output by the model's rate: steady-state RPM × (average input + burndown rate × average output).

When you size a request, keep in mind that:

- Only requests completed through this gateway are counted. Other Bedrock clients in the same AWS account and Region share its quotas.
- Throttled requests aren't recorded, so traffic that already reaches a quota shows that quota as its peak. Ask for headroom above the observed peak.
- Usage is recorded per upstream model ID, not per Region. A model with a region override uses that Region's quotas.
- A [transcription](/docs/speech-to-text) counts as one request, but Bedrock receives one request per chunk of up to 59.5 seconds of speech, up to 6 at a time: an hour of speech makes about 60 or more. Allow for that when you ask for a Voxtral model's RPM.

Automation can read the same values from the management API with the `usage.read` scope. Add `userId` and `groupId`, each repeatable, to limit the scope, and `start` and `end` instead of `timeRange` for a custom window (see [Custom windows](/docs/administration/management-api#custom-windows)):

```bash
curl "https://gateway.example.com/management/v1/analytics/throughput?timeRange=month" \
  -H "Authorization: Bearer $AI_GATEWAY_MANAGEMENT_KEY"
```

The response's `data.summary` covers all models and `data.models` lists each upstream model, most tokens first. Each entry has `requests`, `tokens`, `activeHours`, `steadyStateTpm`, `steadyStateRpm`, `peakTpm`, `peakTpmAt`, `peakRpm`, `peakRpmAt`, `avgInputTokensPerRequest`, `avgOutputTokensPerRequest` and `avgCacheReadTokensPerRequest`. Rates aren't rounded.

The values are computed from every metered request in the range when they're requested, so they include the current minute. Peaks need one-minute detail, which the hourly and daily aggregates behind the charts don't have, so long ranges take longer on busy installations. With 40,000 requests a day, the all-users card took about 1.5 seconds for **Last 30 days** and 12 seconds for **Last 365 days**; one user's took 0.1 and 1 second.

## Credential rotation

<Steps>
  <Step title="Create replacement credentials in AWS">
    Grant only the Bedrock permissions and model access the proxy needs.
  </Step>
  <Step title="Save the replacements">
    Enter the new access key ID, secret access key, and optional session token in the dashboard.
  </Step>
  <Step title="Test an enabled model">
    Confirm a real Converse request succeeds in every region in use.
  </Step>
  <Step title="Revoke the old key">
    Remove the former credentials in AWS only after the test succeeds.
  </Step>
</Steps>

Clearing credentials keeps the service healthy but causes inference to return `provider_not_configured` until credentials are restored.
