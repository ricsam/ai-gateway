title: "Credits and usage"
description: "Understand balances, model pricing, monthly allocations, and request settlement."

Credits are denominated in USD and owned by users. Every model has separate prices per million input and output tokens, with optional prices for cache reads and 5-minute or 1-hour cache writes.

## Check a balance

```bash
curl https://gateway.example.com/v1/credits \
  -H "Authorization: Bearer $AI_GATEWAY_API_KEY"
```

```json
{
  "object": "credit_balance",
  "currency": "USD",
  "balance": 18.42,
  "monthly_allocation": 25
}
```

The key requires `credits.read`.

## Current-month usage summary

Use the native summary when a downstream application needs one request to render USD used, remaining credits, allocation percentage, request count, and token usage:

```bash
curl https://gateway.example.com/v1/usage \
  -H "Authorization: Bearer $AI_GATEWAY_API_KEY"
```

```json
{
  "object": "usage_summary",
  "currency": "USD",
  "period": {
    "start": "2025-03-01T00:00:00.000Z",
    "end": "2025-04-01T00:00:00.000Z",
    "timezone": "UTC"
  },
  "credits": {
    "used": 6.58,
    "balance": 18.42,
    "monthly_allocation": 25,
    "percent_used": 26.32
  },
  "requests": 42,
  "tokens": {
    "input": 12000,
    "output": 3400,
    "cache_read": 2100,
    "cache_write_5m": 500,
    "cache_write_1h": 200,
    "cache_write": 700,
    "total": 18200
  }
}
```

The period is the current UTC calendar month. `period.end` is exclusive. `credits.used` is the metered USD value charged during that period, while `credits.balance` is the current balance. `percent_used` is `used / monthly_allocation × 100`, is not capped at 100, and is `null` when the monthly allocation is zero. The token `total` includes input, output, cache-read, and cache-write tokens.

## LiteLLM-compatible daily activity

For integrations that already understand LiteLLM spend reporting, the gateway implements the core self-service daily activity contract:

```bash
curl "https://gateway.example.com/user/daily/activity?start_date=2025-03-20&end_date=2025-03-27" \
  -H "Authorization: Bearer $AI_GATEWAY_API_KEY"
```

Both dates are required `YYYY-MM-DD` UTC dates, are inclusive, and may span at most 366 days. The response contains descending `results` with LiteLLM-style `metrics`, breakdowns by model, the `bedrock` provider, and opaque API-key ID, plus aggregate `metadata` totals. Playground activity uses the synthetic key label `playground`.

This is a deliberately focused compatibility subset: LiteLLM-specific teams, model groups, endpoints, compression savings, success/failure counts, filters, and pagination are not exposed. The endpoint never accepts a target user ID and always reports only the owner of the presented inference key.

Both usage endpoints require `credits.read`, return `Cache-Control: no-store`, and count only inference ledger events. Monthly resets and administrator adjustments are excluded. Zero-priced model calls are still recorded with their request and token counts even though spend is zero.

## Request admission and settlement

- A user needs a positive balance when inference begins.
- Actual provider usage is priced after the response.
- The ledger records input, output, cache-read, cache-write, total cost, source, model, and request ID.
- A response can cost more than the balance that was available when it began. Settlement records a partial charge rather than making the ledger negative.
- A zero-priced model produces no debit.

An exhausted balance causes subsequent inference calls to return HTTP `402` with code `insufficient_credits`.

## Exactly-once request IDs

Send a stable `X-Request-ID` when an application may retry a completed request:

```bash
curl https://gateway.example.com/v1/chat/completions \
  -H "Authorization: Bearer $AI_GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Request-ID: job-842-attempt-1" \
  -d '{"model":"your-model-id","messages":[{"role":"user","content":"Hello"}]}'
```

Request IDs may contain letters, numbers, `.`, `_`, `:`, and `-`, up to 128 characters. Settlement receipts prevent the same valid request ID from being charged twice.

<Warning>
  A repeated request ID protects credit settlement; it does not turn inference into a response cache. Avoid concurrently sending different logical requests with the same ID.
</Warning>

## Monthly allocations

Administrators can set `defaultMonthlyCredits` per user or apply the value to the union of selected groups. On the first day of each UTC month, the built-in scheduler resets users with a nonzero allocation to that amount. An administrator can also trigger a reset manually.

Users can review balance history, consumption, model mix, token details, and ledger events in **Profile, API & usage**.
